# Salento Local — Cash Out provider verification matrix

**Updated 18 November 2026.** “Genuine event” means Stripe generated an event for an actual test-account state change. “Signed replay” means the event was retrieved from Stripe and a local signature was generated for route testing; it is not Stripe-to-application delivery. “Mocked” means a local provider implementation, not Stripe. Every provider check below used test mode and the dedicated sandbox; no live provider operation was run. No production financial record was modified.

## Evidence retention and next safe test

The local Stripe CLI listener log and isolated SQLite copy were kept only in ignored/private work locations; no secret or payload was committed. The listener and app were stopped. To close the payout forwarding gap, use a new isolated application and database, verify the exact dedicated test platform/connected account and available EUR, create one application-valid test withdrawal, then observe the generated payout event delivered by Stripe CLI in real time. Record Stripe event ID, CLI HTTP status, durable log status, withdrawal/commission state, provider payout retrieval and idempotency keys. If test funds or a safe failed/canceled payout fixture are unavailable, keep those rows **Not verified**; do not simulate production financial state or switch to live keys.
