## Local implementation and operational design

The independent inventory now detects a connected payout destination mismatch, failure balance transaction, late failed/canceled status after local PAID, and connected-account capability/verification failure for accounts tied to withdrawals. The local health scan now includes unresolved legacy FAILED payouts and flags those with recorded payout IDs. Mode guards stop live-key retrieval/reuse of legacy pending Stripe objects and a historical automatic subscription without verified live payment provenance. Focused tests cover these cases. Existing commission amount, 14-day hold, €50 minimum, idempotency/leases, signed webhooks, request blockers and legacy/Cash Out mutual exclusion were not relaxed.

The Stage 8 atomic incident-state file and alert drill are local only. The current combined operations script has send-capable modes and its health call uses the worker secret; it is **not** an independently permissioned production monitor. Railway's one-volume-per-service model also prevents a separate cron service from mounting the web SQLite volume. A dedicated no-send monitor identity, read-only web endpoint, separate durable state, named alert recipient, external watchdog and daily statement close are needed. See the [monitoring runbook](SALENTO_LOCAL_CASHOUT_MONITORING_RUNBOOK.md), [daily reconciliation](SALENTO_LOCAL_CASHOUT_DAILY_RECONCILIATION.md) and [Stage 10B plan](SALENTO_LOCAL_STAGE10B_ACTIVATION_PLAN.md).
